### Seed Data — Therapist Notes

- Added six therapist session notes to `init_db.py` (two per patient) designed to demonstrate the two-sided clinical context that powers the AI insight engine
  - **Alice Johnson** — note from Day 13 (early warning signs, work pressure flagged) and Day 7 (visibly fatigued, sleep disrupted, performance review imminent, sleep hygiene protocol introduced)
  - **Bob Smith** — note from Day 11 (avoidance patterns identified, behavioral activation task assigned) and Day 3 (task completed, affect improved, meaningful insight into anxiety patterns)
  - **Carol Rivera** — note from Day 19 (severe fatigue, tearfulness, safety assessed, PCP referral initiated) and Day 14 (slight improvement, PCP scheduled, disengagement risk flagged explicitly)
- Carol's notes end 14 days ago with no further reflections — intentional gap that demonstrates the engagement flag and disengagement risk narrative Claude surfaces
- Notes are timed to align with the existing reflection data so time-window filtering (week/month/year) produces meaningfully different summaries

#### What makes this demo-ready

- Each patient tells a distinct clinical story: Alice is a declining acute case, Bob is a recovery arc, Carol is a disengagement risk
- Therapist notes add context the patient reflections alone can't capture (affect, demeanor, safety assessment, assigned tasks)
- Claude synthesizes both sides into a narrative that would genuinely save a therapist time before a session

### On-Demand AI Insight Generation

#### Behavior change

- Removed the `useEffect` that auto-fetched insights whenever `patientId` or `window` changed — previously burned an API call every time the user selected a patient or toggled the window
- Insights are now generated only when the user explicitly clicks a button

#### Empty state

- When a patient is selected with no summary yet, the panel shows: "No summary yet. Select a time window above and generate a pre-session brief." with a prominent "Generate Pre-Session Summary" button
- Selecting a different time window updates the selector only — no call is made until the user clicks Generate

#### Generated state

- Once generated, the summary persists in component state for the session
- "Generated by Claude · claude-opus-4-7" attribution sits at the bottom of the panel
- A "Regenerate" button (outlined, clearly interactable) lets the therapist request a fresh summary — useful after adding new session notes or switching time windows

#### Learnings

- Auto-fetching AI results on every state change is the wrong default for expensive, latency-sensitive calls — user intent should gate the request
- Empty states with a clear call-to-action communicate capability better than auto-loading placeholders that appear and disappear
- Component state is sufficient for session-scoped AI results — persistence across sessions would require a DB model, which is out of scope for MVP
